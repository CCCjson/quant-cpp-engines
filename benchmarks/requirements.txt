# Python 参照引擎与 parity 门禁的依赖
#
# 为什么要钉版本：parity_gate.py 做的是**逐位**比较——七项经济指标要求
# C++ 与 Python 两侧差值为 0.00e+00，不是「在容差内」。Python 侧的数字由
# pandas/numpy 算出，所以这两个库的版本理论上会影响门禁结论。版本不钉，
# 门禁某天变红时就分不清是 C++ 改坏了还是 pandas 换了实现。
#
# 下面是 benchmarks/results/backtest.json 的 environment 块里记录的、
# 当初产出全部跑分数据的那一组版本：
pandas==2.1.4
numpy==1.26.3
loguru
#
# ── 一个已验证的旁注 ──
# 2026-09-11 用 Python 3.13.11 + pandas 2.3.3 + numpy 2.3.5 重跑过 parity 门禁，
# 结果 results/parity.json **逐字节相同**，七项仍全部 0.00e+00。
# 也就是说这七项指标对 pandas 大版本变化不敏感（它们走的是基础算术，
# 没碰到 ddof / ewm 那些有口径分歧的实现——那两处本来就登记在
# 「已知口径差异」里、不参与门禁）。
#
# 仍然钉版本，是因为「实测不敏感」和「保证不敏感」是两件事：
# 钉住之后门禁变红就只有一种解释，那才是门禁该有的性质。
